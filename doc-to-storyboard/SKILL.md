# 文档转短片：资产先行

## 这个 skill 的终点

一条从头到尾**前后一致**的短片。一致性不靠提示词里反复描述，靠**资产**：人物、场景、道具、细节先各自变成一张固定的图，所有镜头都去引用这些图。

终点默认停在「策划包 + 资产表 + 提示词」。用户要成片时，按资产逐段生成，不要在没有确认资产前就开始跑视频。

## 为什么必须资产先行

同一个道具，写两遍文字描述，出来是两件东西。同一张脸，写五遍，会有五个年龄。**文字锁不住外观，图片才锁得住。**

所以顺序是死的：**先资产，后镜头**。反过来做（先写镜头再补资产）等于每镜各生成一次，一致性只能靠运气。

## 开工前要问全的四件事

| 要问 | 为什么不能猜 |
|---|---|
| 素材在哪 | 剧本全文 / 文档路径。没有素材不要凭空编故事 |
| 终点规格 | 单条 15s、30–60s、更长分段。决定拆几场、资产做到多细 |
| 风格 | 内置风格卡 / 参考图 / 一句感觉 |
| 要不要 3D | 简单对话戏、单机位，2D 就够；要换机位、转角度、同一空间多镜，才值得上 3D |

四项一次问全。已经说清的就不要再确认。

## 六个阶段

### 阶段 0 · 拆幕成场

通读素材，按幕/场切开，每场回答：谁在场、在哪、发生什么、持续多久。

**场的划分标准**：空间变了、时间跳了、人物组合变了，三者任一变化就换场。一场对应一条时间轴，对应一套场景资产。

写一张场表（`场号 / 地点 / 时间 / 在场人物 / 时长 / 一句话内容`），这是后面所有拆分的地基。

### 阶段 1 · 建资产表

读 `references/asset-pipeline.md`。把每一场需要的资产拆成四类：

| 类 | 编号 | 拆什么 | 典型数量 |
|---|---|---|---|
| 人物 | `P1` `P2`… | 每个出场人物一套：定妆正面、侧面、关键表情 | 每人不低于 2 张 |
| 场景 | `S1` `S2`… | 每个空间一套：主视角 + 反打视角（反打必须做，否则跨镜会换屋） | 每场不低于 2 张 |
| 道具 | `O1` `O2`… | 被人物接触、或承担叙事的物件：单品格 + 带手比例格 | 每件 1–2 张 |
| 细节 | `D1` `D2`… | 材质、光位、空气介质等会跨镜复现的表面：一张特写 | 按需 |

资产表用 `assets/asset-registry.md` 的模板，落成一份 Markdown。**每个资产都要有编号、名称、出现场次、状态变体、是否上 3D、文件路径。**

### 阶段 2 · 生产 2D 资产

按资产表逐项生成定妆图，规范见 `references/asset-pipeline.md` 第二节：

- 人物：**正面中景**为主图，配一张**侧面**；有情绪戏的再补 1–2 张**关键表情**
- 场景：**主视角**（叙事常用机位）+ **反打视角**（从对面拍回去），两张都要有明确光位
- 道具：**单品格**（干净背景或场景内） + **带手比例格**（一只手入画当尺度参照）
- 细节：材质特写，一件一张

写提示词的规矩不变：风格卡定调、身体参照写尺寸、负面约束必写、禁项必落。见 `references/style-cards.md`、`references/materials.md`、`references/storyboard-and-prompts.md`。

### 阶段 3 · 2D 闸门（不过不进下一步）

每个资产过三关，全过才标 `已确认`：

| 关 | 查什么 |
|---|---|
| 身份关 | 和设定一致：年龄、脸、发型、服装；道具的类别与形态特征对不对 |
| 比例关 | 尺寸靠人手/身体参照判断；道具是否被画大或画小 |
| 干净关 | 无多余人物、无烧制字幕、无结构穿模、无悬空 |

**没过就重出，不要凑合往下走。** 一张图错了，后面所有引用它的镜头全错，改起来是重跑整条片子。

确认后的资产写进资产表，状态改 `已确认`，文件按 `ASSET-ID_视角.png` 命名归档。

### 阶段 4 · 3D 资产（按需）

读 `references/asset-pipeline.md` 第三节。**3D 不是交付物，是「多机位静帧的发生器」。**

- 什么时候上：同一空间有多个机位、人物要转身或走动、镜头有环绕或明显透视变化
- 什么时候不上：固定机位对话戏、单镜特写——2D 三视角够用，上 3D 是浪费
- 怎么做：用已确认的 2D 定妆图做 image-to-3D 得到 GLB；在 3D 里按分镜表的机位摆相机，渲染每个机位的静帧；**这些静帧替换 2D 图，成为视频生成的参考图**
- 验收：3D 渲染的静帧，应与对应机位下的 2D 定妆图基本一致。差太多说明 3D 建歪了，回退用 2D

没有 3D 工具时的降级：用 2D 多视角（正面/侧面/背面/俯视）当 multi-view 参考，或直接为每个机位单独出一张 2D 静帧。

### 阶段 5 · 按资产生成视频

这时才写镜头。顺序：

1. 按场拆分镜表（切点、时长、景别，见 `references/storyboard-and-prompts.md`）
2. 每条视频的提示词**按固定顺序引用资产**：图 1 人物 → 图 2 场景 → 图 3 道具
3. 提示词开头声明每张图的作用：「图 1 为人物参考，图 2 为空间与光位参考，图 3 为道具与比例参考」
4. 落定句明确落定在哪张图建立的画面上
5. 一个动作必须写明施动者，禁止被动句

**镜头只能引用已确认的资产。** 状态不是 `已确认` 的资产，不许出现在提示词里。

### 阶段 6 · 拼接与连贯

多段拼接的断层处理见 `references/storyboard-and-prompts.md` 第九节：底噪同源、配乐跨组规划、景别交替、J-cut / L-cut、电平匹配。

同一镜头若有多条候选，**可取各条可用片段在预设切点处互换重拼**——一段废片里往往有半段能用。

## 十二条硬规则

1. **资产先于镜头**。没有确认的资产，不写镜头提示词。
2. **资产编号即身份证**。每条提示词必须写明引用了哪些编号；没引用编号的提示词视为未接资产，不许提交。
3. **资产一改，引用它的镜头全部作废**。改脸、改道具、改场景光位，都要重跑受影响的镜头。这是资产先行的代价，也是它管用的原因。
4. **人物描述段逐字复用**——全文存在资产表里，提示词里照抄，不改写不缩写。
5. **台词标签原样保留**：`<d>[Chinese] 台词。</d>`，一行一句，不翻译不改格式。
6. **切点落在台词之后 ≥0.3s**。
7. **一组不超过 4 镜**。
8. **时长必须是整数秒**。接口只收整数，小数在提交阶段就被拒。
9. **不写空词**。「电影感」「高级感」换成介质、焦段、光线、材质。
10. **负面约束必须显式写进提示词**。不笑、不看镜头、不要字幕、结构要完整——不挡它就会加。
11. **动作必须写明施动者，禁止被动句**。写「桶被推过台面」出来就是桶自己滑过去、没人碰。
12. **静帧不过关不跑视频**。参考图会把首帧的姿态、表情、结构缺陷整条搬进视频，视频提示词盖不过它。

## 三道闸门

| 闸门 | 在哪 | 不过怎么办 |
|---|---|---|
| 资产关 | 阶段 3 | 重出该资产，不许带着缺陷进 3D 或视频 |
| 3D 关 | 阶段 4 | 渲染静帧与 2D 定妆图不一致 → 回退用 2D |
| 视频关 | 阶段 5 | 单条不合格 → 重跑该条，不要动已确认的资产 |

**任何一关都别用"先跑看看"绕过。** 一张资产图的成本远低于一条视频。

## 交付

一份 Markdown，八节：

1. 创作定位
2. 风格卡
3. 场表
4. **资产表**（四类资产 + 描述段 + 状态 + 文件）
5. 剧本
6. 分镜表（带资产引用列）
7. 提示词（开头带资产声明）
8. 执行说明（闸门状态、失效传播、风险）

用 `assets/deliverable-template.md` 的骨架，资产表用 `assets/asset-registry.md` 的模板。文件命名 `项目名-策划包.md`，资产文件放在同目录的 `assets/` 下。

交付时说清：总时长、场数、镜数、分几组、每条视频时长（整数秒）、资产总数与已确认数、哪些资产还没过闸门。
